# Kite POS on Android

A native Android app (Kotlin + Rust) that runs the retail register from
`examples/ui/pos.ui`. The `.ui` file is compiled to Rust at build time, so the
app contains no interpreter. It is laid out for tablets in landscape
(about 1280×800 dp).

```
MainActivity (Kotlin) ── KiteView (android.view.View)
                            │  size, touch, keys, IME text      ▲ onKiteCallback(name, args)
                            ▼  JNI (generated by kite_view_jni!) │
                         libkitepos.so (Rust)
                            Register component (from pos.ui) → software renderer → Bitmap
```

- `native/`: the Rust `cdylib`. `build.rs` compiles `pos.ui`, and
  `kite_android::kite_view_jni!(Register)` generates the JNI functions.
- `app/src/main/java/dev/kite/KiteView.kt`: a reusable View. It renders
  frames into a `Bitmap`, forwards touches, shows the soft keyboard while a
  Kite text field has focus, and delivers callbacks.
- `MainActivity.kt`: hosts the register and shows a toast on `checkout`.
- `app/src/androidTest/.../PosFlowTest.kt`: rings up a cash sale with real
  touch and key events and checks the totals.

## Build and run

Requirements: Android Studio or the Android SDK, an NDK, Rust 1.80+, and

```bash
rustup target add aarch64-linux-android x86_64-linux-android
cargo install cargo-ndk
```

Then open `examples/android-pos` in Android Studio and press Run, or:

```bash
cd ui-framework/examples/android-pos
./gradlew installDebug          # builds libkitepos.so via cargo-ndk first
./gradlew connectedDebugAndroidTest
```

The Gradle `preBuild` step runs `cargo ndk` for `arm64-v8a` and `x86_64`.
cargo-ndk finds the NDK via `ANDROID_NDK_HOME` or the SDK's `ndk/` folder.
Use a tablet emulator profile (for example Pixel Tablet or Nexus 10) in
landscape.

CI (`.github/workflows/kite-android.yml`) builds the APK, boots an API 34
x86_64 emulator, runs the sale test, and uploads the APK, screenshots and
logcat as the `kite-android-pos` artifact.

## Current limits

- The layout targets tablets. It does not fit a phone screen.
- The soft keyboard sends committed text. There is no composition
  underline or autocorrect.
- No TalkBack accessibility yet.
- Rendering is a full CPU repaint per change into a Bitmap.
